# さとのわ 出席と日々の記録

職員用のWebアプリ。スマホで実際の来所日と内部デイリーを入力し、PCで個人年間出席簿を確認・出力します。

## 現在の機能

- 固定曜日と適用開始日、在籍期間、臨時開校・休校を登録
- 来所・来所なし・未確認を区別。振替でも実際の来所日に記録
- 内部デイリーと職員専用メモ、変更者・訂正履歴
- 日別の〇、月ごとの来所日付一覧、年間累計を掲載した帳票
- 保護者向け・在籍校向けの共有文を別々に選択・編集
- 確定時の報告内容を保存。後の訂正は以前の報告を変えない
- PDF画面の印刷ボタンから「PDFに保存」。自動送信はしない
- 全体出席簿CSVと管理者用JSONバックアップ

## 保存と権限

Sitesの非公開アクセスとChatGPTログインを使用。実際の記録はCloudflare D1に保存し、ブラウザのローカル保存は使用しません。最初の管理者初期化では、Sitesの実行時設定 `SCHOOL_OWNER_EMAIL` とログインした所有者のメールを照合します。初期化後は保存したログインIDで識別します。以後、登録済みメールとログインIDを照合し、管理者1人・職員2人を想定します。

職員は来所とデイリーの記録ができ、管理者だけが子どもの登録・開校日変更・報告確定・PDF出力・バックアップを行えます。保護者連絡先と確定報告は職員向けAPIレスポンスに含めません。未ログインや未登録のアクセスはサーバー側で拒否します。複数の職員が同時保存した場合は、後の更新を拒否して再確認を促します。

職員の登録だけではSites自体の閲覧権限は追加されません。管理者が別途許可します。招待メールや保護者・学校への送信は行いません。実データの初期状態は空です。架空データモードの変更はメモリ内だけに保持し、再読込で消えます。

## 開発・起動

Node.js 22.13以上とnpmが必要です。

ローカルプレビュー用の `.dev.vars` に `SCHOOL_OWNER_EMAIL=seedy@sites.test` を設定します。本番の管理者メールはSitesの実行時設定に登録済みです。実際のメールアドレスをソースや公開ファイルに書き込まないでください。

1. `npm run install:ci`
2. `npm run build`
3. 下記のローカルD1手順に従い、`drizzle/0000_school.sql`をプレビューDBに適用（初回のみ）
4. `npm run dev`

初期SQLはSQLiteで検証済みですが、依存関係が未準備のためDrizzle生成による照合は未実施です。将来スキーマを変更するときは、初期マイグレーション履歴を確認してから新規の変更だけを追加してください。初期SQLの再適用はしないでください。

ローカルD1初期化コマンド：

```text
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_school.sql
```

テスト：`node --test tests/*.test.mjs`

GitHubへの保存先は `satonowa311-coder/shutuseki` です。GitHub Actionsで集計・権限チェックと本番用ビルドを実行します。成功すると `satonowa-build` にビルド結果が保存されます。GitHubへのコード保存だけではアプリは公開されません。

GitHub Pagesではサーバー側の認証と共有保存を実行できないため、この版をそのままPagesに公開する設定はありません。Sitesの非公開ホスティング向けの構成です。公開先を変える場合は、ログイン・保存処理を対応させてから実データを利用してください。

祝日データは2026・2027年のみ。出典：[内閣府「国民の祝日について」](https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html)。他年度に使う前に休日カレンダーを更新してください。
